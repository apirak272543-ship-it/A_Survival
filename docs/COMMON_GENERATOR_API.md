# A_Survival Common Generator API

**สถานะ:** foundation checkpoint — backend/data tooling only

เอกสารนี้กำหนดสัญญากลางสำหรับเครื่องมือสร้าง content ของ A_Survival โดยแยกหน้าที่ของ generator ออกจาก game runtime อย่างชัดเจน Generator สร้าง artifact แบบ deterministic จาก input กับ seed; validator ตรวจ artifact; registry จัดการ id/version; preview แสดงข้อมูลสรุป; save/export อนุญาตเฉพาะ artifact ที่ผ่าน validation แล้ว เกมผู้เล่นไม่มีปุ่มหรือ route สำหรับเรียก API นี้

## Pipeline

```text
Generator Input + Seed
        ↓
Registered Generator Version
        ↓
Generate Once
        ↓
Plugin Validation
        ↓
Asset/Data Reference Validation
        ↓
Deterministic SHA-256 Content Hash
        ↓
Preview / Save / Export
        ↓
Dependency / Reference Validation
        ↓
Content Registry or Runtime Import
```

## Contract ที่มีจริง

`server/generators/commonGeneratorApi.ts` มี `CommonGeneratorRegistry`, `GeneratorPlugin`, `GeneratorArtifact`, `GeneratorAssetRef`, `GeneratorProvenance`, `GeneratorValidationResult` และ `GeneratorValidationError` โดยรองรับ `Generate`, `Validate`, `Preview`, `Save`, `Export`, `Version` และ version list ตามสัญญากลาง

Artifact ใช้ schema `a-survival.generator-artifact.v1` และเก็บ `generatorId`, semantic version, `kind`, normalized seed, input, output, asset references, SHA-256 content hash และ provenance ที่ระบุว่าเกิดจาก backend generator. ค่า `generatedAt` และ `savedAt` เป็น metadata จึงไม่ทำให้ content hash ของ input/seed/output เดียวกันเปลี่ยน

Asset reference ต้องระบุ logical `assetId`, domain kind และ source (`generated`, `starter-authored`, `provided` หรือ `reference-only`). หากเป็น reference-only ต้องมี `provenanceRef`; หากมี SHA-256 ต้องเป็นค่า hexadecimal 64 ตัวอักษร. ข้อมูลนี้เป็น metadata/validation boundary ไม่ใช่การอนุญาตให้นำ reference asset มาเป็น runtime asset

## Dependency graph contract

`server/generators/dependencyGraph.ts` เพิ่มสัญญา `a-survival.dependency-graph.v1` สำหรับตรวจสายพึ่งพาแบบ deterministic ก่อน registry. แต่ละ node ต้องมี `key`, `kind`, `generatorId`, `generatorVersion`, `schemaVersion`, `seed`, `rulesVersion`, `contentHash` และรายการ dependency ที่ระบุ `required`, kind, generator/version ที่คาดหวัง, compatible versions หรือ content hash ได้ตามกรณี. ระบบเรียง node และ edge ด้วย key ที่ stable และคืน `topologicalOrder` ให้ dependency มาก่อน dependent.

Validator ตรวจ node/dependency ซ้ำ, reference ที่ required หาย, kind/generator/version/hash mismatch และ cycle. Optional dependency ที่หายจะไม่ block แต่ required dependency ที่หายหรือข้อผิดพลาดอื่นทำให้ graph เป็น invalid. `creator.dependencyGraph.preview` เป็น admin-only preview ใน Workbench; ไม่บันทึก registry, ไม่สร้าง binary, ไม่ import/cache/publish และไม่เปลี่ยน Obsidian Frontier player runtime. Core graph นี้เป็นก้าวแรกของ dependency validation. `contentCatalogDependencyGraph.ts` ใช้ `content.catalog` ที่ register อยู่จริง generate artifact จาก seed เดิม แล้วแปลง category asset และ sampled definitions เป็น graph nodes พร้อม hash/reference checks; จึงไม่ใช่ static graph fixture. `questContentCatalogDependencyGraph.ts` ต่อด้วย `quest.progression` artifact จริง, planned/playable map metadata, sampled quest prerequisites และ objective/reward references ไปยัง catalog nodes; reference ที่ไม่พบถูกปล่อยให้ validator block ตาม contract และ future map nodes ยังมี runtime import/cache/player visibility เป็น false. `worldStructureDependencyGraph.ts` ต่อด้วย `world.generator` จริงบน `obsidian-frontier`, โครงสร้างจาก `structure.placement` จริง, blueprint/placement hashes และ world-bounds/placement rejection summary; adapter นี้เป็น preview ของแผนที่เดียว ไม่สร้าง future map และ graph runtime policy ยังปิดทั้งหมด. `itemContentCatalogDependencyGraph.ts` ต่อด้วย `item.universal` จริงและ `content.catalog` จริง, ตรวจ balance budget, category/resource references และส่ง missing references เป็น required graph edges เพื่อ block ก่อน registry; item preview ไม่สร้าง binary และไม่ import/cache/publish เข้า player. `worldBlockContentCatalogDependencyGraph.ts` ต่อด้วย `world.generator` จริงบน `obsidian-frontier`, ใช้ `blockModules` เป็น owner ของ block definitions/drop/block-item/asset references, sample block/resource nodes แบบ bounded และต่อเข้ากับ `content.catalog`; runtime block-item IDs และ block asset IDs ที่ catalog generator ยังไม่แทนด้วย definition ที่ตรงกันจะถูกแสดงเป็น required missing edges แทนการสร้างข้อมูลปลอม. World/block preview ไม่เขียน registry และไม่ import/cache/publish เข้า player. `structureBlockContentCatalogDependencyGraph.ts` ต่อด้วย `worldStructureDependencyGraph` จริง, world-owned structure block groups, `structureGenerator` blueprint/child relations, `blockModules` semantics และ `content.catalog`; blueprint asset, required child, block asset, drop และ block-item references ที่ไม่มี node ตรงกันถูกเก็บเป็น required missing edges พร้อม reason เพื่อ block ก่อน registry. Structure preview ยังเป็น admin-only developer preview และไม่ import/cache/publish เข้า player. `worldBiomeResourceContentCatalogDependencyGraph.ts` ต่อด้วย `world.generator` จริงบน `obsidian-frontier`, สรุป biome IDs/cell counts และ sampled `GeneratedResourceNode` แล้วเชื่อมไปยัง `content.catalog`; catalog ที่ยังไม่มี biome category หรือ `ore.aether.block` definition จะถูกแสดงเป็น required missing edges พร้อม reason แทนการสร้าง definition ปลอม. Biome/resource preview ไม่เขียน registry และไม่ import/cache/publish เข้า player. `worldSpawnDependencyGraph.ts` ต่อด้วย `world.generator` จริงบน `obsidian-frontier`, สร้าง sampled spawn nodes จาก `GeneratedSpawnPoint`, เชื่อม biome context และ `structureId` context ที่มีจริง และเก็บ species IDs ที่ยังไม่มี mob/NPC generator definition เป็น required missing edges; จึงไม่ประดิษฐ์ ecology หรือ runtime spawn definition เพื่อให้ graph เขียว. World spawn preview เป็น admin-only developer preview ไม่เขียน registry และไม่ import/cache/publish เข้า player. `worldSpawnLootDependencyGraph.ts` ต่อด้วย `world.generator` จริงบน `obsidian-frontier` และ `content.generator`/`generateLootDrop` จริง, สร้าง loot/drop item nodes สำหรับ sampled regular/boss spawns แบบ deterministic และเชื่อมกลับไปยัง spawn, biome และ structure context. Species definitions ที่ยังไม่มี mob/NPC owner และ procedural item asset bindings ที่ยังไม่มี verified manifest จะถูกเก็บเป็น required missing edges พร้อม reason แทนการสร้าง definition หรือผูก asset ปลอม. Spawn→loot preview ไม่เขียน registry และไม่ import/cache/publish เข้า player. `proceduralContentCatalogDependencyGraph.ts` ต่อด้วย `content.generator`/`generateProceduralWeapons` จริงกับ `content.catalog` จริง, สร้าง bounded procedural weapon root/item nodes และเชื่อม category asset ที่ตรงกันเมื่อมี. Exact generated definition IDs, magic category ที่ catalog ยังไม่มี และ texture asset bindings ที่ยังไม่มี verified manifest จะถูกเก็บเป็น required missing edges พร้อม reason แทนการสร้าง catalog definition หรือ asset binding ปลอม. Procedural content preview เป็น admin-only developer preview ไม่เขียน registry และไม่ import/cache/publish เข้า player. `plantContentCatalogDependencyGraph.ts` ต่อด้วย `generateWorldPlantCatalog` จริงจาก runtime plant owner จำนวน 300 รายการ, `getPlantDefinition` สำหรับ exact plant asset, และ `content.catalog` จริง; sampled plant nodes เชื่อม root/category assets และเก็บ seed/harvest definition, soil, biome, runtime plant asset และ seed icon ที่ยังไม่มี exact node เป็น required missing edges พร้อม reason. Plant preview คง biome `obsidian-frontier`, จำกัด sample 1–32 รายการ, ไม่สร้าง plant/seed/harvest definition ใหม่ และไม่เขียน registry หรือ import/cache/publish เข้า player. `proceduralUniversalItemDependencyGraph.ts` ต่อด้วย `content.generator`/`generateProceduralWeapons` จริงเข้า `item.universal` registry/plugin จริง โดย map category/element/role/progression และสร้าง universal item artifacts ที่ผ่าน canonical balance/validation เมื่อ contract รองรับ. Procedural asset IDs ที่ยังไม่มี verified manifest และ Universal Item validation failures จะถูกเก็บเป็น required missing edges พร้อม reason; adapter จำกัด count 1–8, maxPowerBudget 1–100 และยังคง runtime import/player visibility/cache เป็น false. ไม่มีการสร้าง item definition ปลอมเพื่อทำให้ graph เขียว และไม่มีการ register/publish อัตโนมัติ. `animationAssetDependencyGraph.ts` ต่อด้วย `animation.profile` registry output จริง, active `arcane-frontier-voxel-pixel` manifest และ `metadata/animations.json` จริง; profile states ถูกเทียบกับ runtime metadata และ exact animation asset entry/kind ที่ขาดหรือไม่ compatible จะเป็น required missing/mismatch edges. Adapter จำกัด seed 1–128 ตัวอักษรและใช้ runtime pack เป็น read-only preview; ไม่เขียน metadata, ไม่สร้าง clip/asset ใหม่, ไม่ register/publish และคง runtime import/player visibility/cache เป็น false. `structureSpawnReconciliationDependencyGraph.ts` ต่อด้วย `world.generator` output จริง, `structure.placement` blueprint/placement output จริง และ world spawn points จริงบน `obsidian-frontier`; structure blueprint NPC/mob spawn intent ถูกจับคู่กับ world spawn role/species ตาม bounded spatial proximity พร้อม world structure context nodes. Spawn intent ที่ไม่พบ, species ที่ไม่ตรง หรือ spawn ที่อ้าง structure context ที่ไม่มี placement จะเป็น required blockers พร้อม reason; adapter ไม่สร้าง mob/NPC definition และไม่เชื่อม hardcoded map encounter runtime ที่ยังเป็น owner แยก. Preview จำกัด radius 16–64 และ sampled spawn 1–64, ไม่เขียน registry และคง runtime import/player visibility/cache เป็น false. `worldSpawnLootUniversalItemDependencyGraph.ts` ต่อด้วย `world.generator` spawn/biome/structure context และ `content.generator` loot/drop records จริง แล้ว reuse `buildUniversalItemInput` ของ canonical procedural adapter เพื่อส่งแต่ละ drop เข้า registered `item.universal` engine. Loot/drop nodes เดิมถูกนำมาเป็น parent ของ Universal Item output; asset binding และ world species/context blockers จาก loot owner ถูกคงไว้, ส่วน validation failures ที่เกิดจาก `maxPowerBudget` จะเป็น required `item.universal.output` blockers พร้อม artifact summary ไม่ fabricating definition. Preview จำกัด radius/sample 16–64, budget 1–100, ไม่ register/publish และคง runtime import/player visibility/cache เป็น false. `map001EncounterDependencyGraph.ts` ต่อด้วย active MAP_001 `resolveMap001Encounter` owner จริง (Distress Pod และ Leyline Monolith) และ sampled `world.generator` spawn/loot graph จริงบน `obsidian-frontier`; telegraph-to-active event outputs ถูก deterministic แล้วจับคู่กับ expected Glass Stalker/Void Reaper spawn role/species, spawn node และ loot node. Coverage ที่ไม่ครบหรือ loot context ที่หายถูกเก็บเป็น required missing edges พร้อมเหตุผล โดยไม่แก้ encounter gameplay, ไม่สร้าง mob/NPC definition และไม่สร้าง spawn ปลอม. Preview จำกัด radius 16–64 และ sampled spawn 1–64, admin-only, ไม่ register/publish และคง runtime import/player visibility/cache เป็น false. `map001StoryGateDependencyGraph.ts` ต่อด้วย active MAP_001 encounter outputs และ `quest.progression` registry owner จริง; สร้าง prerequisite ของ Obsidian Frontier จำนวน 20 เควสสำหรับ planned `story-map-002`, ตรวจ `playable`/`planned` runtime boundary จาก story system และปล่อย `map001-encounter-completion:boss-defeated` เป็น required missing dependency เพราะ encounter owner ปัจจุบันมีเพียง boss-active ไม่ใช่ completion signal. Preview จำกัด mapCount 2–3, ไม่อนุมานการจบ encounter, ไม่เปิด future-map runtime import และไม่ register/publish/cache. `storyProgressionContractDependencyGraph.ts` ต่อด้วย story progression runtime owner จริง (`normalizeStoryProgressState`, `completeStoryQuest`, `getStoryProgressSummary`) และ registered `quest.progression` artifact แบบ read-only; สร้าง state ผ่าน completion API ต่อเนื่อง 0–20 เควส แล้วตรวจ current quest, contiguous completed prefix, Obsidian Frontier playable contract และ next story map ที่ยัง planned/runtime-import-denied. Mismatch ของ runtime state หรือ map boundary จะเป็น required graph blockers; preview จำกัด completedQuestCount 0–20, ไม่เขียน session, ไม่ register/publish และคง runtime import/player visibility/cache เป็น false. `storyMapCachePolicyDependencyGraph.ts` ต่อด้วย story progression runtime contract, `RUNTIME_MAP_ID`/`resolveDirectMapId`/`isRuntimeMapAllowed` จาก direct-route, `MAP_REGISTRY` และ `MAP_CACHE_NAME`/`prepareMapModule` policy owner. Adapter ตรวจรายการ map ที่ร้องขอแบบ bounded โดยไม่เรียก `prepareMapModule`, ไม่เขียน Cache Storage/localStorage และไม่สร้าง cache record; Obsidian Frontier เป็นรายการเดียวที่ selection/cache eligible ส่วน future story map จะ fallback ไป runtime map และคง required blockers เมื่อไม่มี registry definition หรือ runtime approval. Route/UI เป็น admin-only Thai preview และ graph runtime policy ยังคง `{ runtimeImportAllowed: false, playerVisible: false, cacheable: false }`. Map-cache owner เพิ่ม guard ที่ `prepareMapModule` และ `hasCachedMapModule` เพื่อ deny future map ก่อน network/cache work. Generator ทุก domain ยังต้อง migrate มา emit และ validate graph ของตัวเองเป็น checkpoint แยก.

`storyOfflineMapStateDependencyGraph.ts` ต่อด้วย story runtime/cache policy, `RUNTIME_MAP_ID`/direct-route, `MAP_REGISTRY` และ `defaultOfflineMapState`/`normalizeOfflineMapState` จริง เพื่อยืนยัน map+player offline namespace แบบ deterministic. Active Obsidian Frontier เป็น namespace เดียวที่ cache/state-write policy อนุญาต; future map ยัง normalize เป็น data-only ได้เพื่อรองรับ backend/planned data แต่ `saveOfflineMapState` ปฏิเสธก่อน IndexedDB write และ graph จะสร้าง required blocker เมื่อ selection/cache/runtime approval ไม่ผ่าน. Preview route ใช้ `storyOfflineMapStatePreview` ภายใต้ `adminProcedure`, ไม่อ่านหรือเขียน IndexedDB/Cache Storage, ไม่เรียก `prepareMapModule`, ไม่สร้าง cache record และคง runtime import/player visibility/cache เป็น false. Workbench แสดง assessment ของแต่ละ map, player namespace, normalization identity และจำนวน future write blockers เป็นภาษาไทย.

`questGameplayEventDependencyGraph.ts` ต่อด้วย `generateQuestProgression` จริงของ MAP_001 (`obsidian-frontier`) และ runtime action contracts ที่ตรวจพบจาก `ArcaneFrontier`, `worldFarmSystem`, `worldStorageSystem` และ `syncActionValidation`. ทุก assessment จับ objective kind/target/required count เข้ากับ event owner, event type, target binding และ required payload fields โดยไม่ emit หรือ submit gameplay action. ขณะนี้ objective `visit`, `collect`, `talk`, `craft` และ `defeat` ยังไม่มี canonical runtime event owner; `mine` มี `block-break` แต่ payload ยังไม่ระบุ mined/drop identity; `harvest` มี owner แต่ pending-action bridge ยังไม่ส่ง `plantId`; และ `place-block` ยังพิสูจน์ไม่ได้ว่า quest target ตรงกับ `itemDefinitionId`. ดังนั้น MAP_001 sample จะยังเป็น required blockers ตามจริง ไม่ fabricate completion และไม่เปิด future map.

Adapter นี้สร้าง graph nodes จาก quest progression กับ gameplay action owner แบบ deterministic และใช้ `validateGeneratorDependencyGraph` โดยคง policy `{ runtimeImportAllowed: false, playerVisible: false, cacheable: false }`. Input จำกัด sample quest 1–20 และ completed quest 0–20; `completedQuestCount` เป็นข้อมูลจำลองเพื่อแสดง boundary เท่านั้น ไม่เขียน story session, ไม่เรียก cache/IndexedDB, ไม่ register/publish และไม่เปลี่ยน `ArcaneFrontier` หรือ `storyProgressionSystem`. Route `creator.dependencyGraph.questGameplayEventPreview` และ Thai Workbench จึงเป็น developer-only read-only preview; UI แสดง event/target blockers และย้ำว่าไม่ส่ง event และไม่ complete quest อัตโนมัติ.

`questRewardRuntimeDependencyGraph.ts` ต่อด้วย `generateQuestProgression` ของ MAP_001 และใช้ owner ที่มีอยู่จริงจาก `catalog.ts` (`getItemDefinition`, `createMapRewardInstance`) กับ `ArcaneFrontier/rewardHandler`. Adapter ตรวจว่า reward item definition และ reward-instance factory รองรับ item reward หรือไม่, แล้วตรวจ bridge ที่ต้องมีจาก `completeStoryQuest` ไปยัง reward handler รวมถึง ability runtime owner สำหรับ `ability.story.001` ที่ quest สุดท้ายสร้างขึ้น. ปัจจุบัน item definition และ factory รองรับ sample reward ได้ แต่ยังไม่มี caller สำหรับ quest reward dispatch และยังไม่มี ability runtime owner; จึงคงทุก assessment เป็น required blocker โดยไม่แจกของ ไม่เขียน inventory ไม่ปลดล็อก ability และไม่เปลี่ยน story state. Input จำกัด sample quest 1–20 และ completed quest 0–20; `completedQuestCount` เป็นข้อมูลจำลองเท่านั้น.

Graph ใช้ `a-survival.dependency-graph.v1` และคง policy `{ runtimeImportAllowed: false, playerVisible: false, cacheable: false }`. `creator.dependencyGraph.questRewardRuntimePreview` และ Thai Workbench เป็น developer-only read-only preview ที่แสดง item definition, reward-instance factory, dispatch caller และ ability owner ตามหลักฐาน source จริง. Adapter ไม่เรียก `completeStoryQuest`, ไม่เรียก `rewardHandler`, ไม่สร้าง persistent `ItemInstance`, ไม่เขียน IndexedDB/Cache Storage/DB, ไม่ register/publish และไม่เปิด future map.

`questRewardInventoryDependencyGraph.ts` ต่อด้วย `generateQuestProgression` จริง, catalog `getItemDefinition`/`createMapRewardInstance` และ `inventorySystem/addItemToContainer` แบบ dry-run. Adapter จำลอง inventory 40 ช่องจากจำนวน `inventoryUsedSlots` ที่ bounded แล้วตรวจว่า reward instance จะถูกเพิ่มแบบ atomic ได้หรือมี capacity blocker; การจำลองใช้ clone และไม่เปลี่ยน inventory/player/story state. Item definition กับ factory ที่มีจริงจะแสดงเป็น evidence แต่ทุก reward ยัง `supported:false` จนกว่าจะมี canonical caller จาก `completeStoryQuest` ไปยัง reward dispatch และ ability runtime owner ที่ตรวจสอบได้. เมื่อ inventory เต็ม ระบบเพิ่ม required `inventory-capacity` dependency ตาม reward quantity แทนการตัด reward หรืออ้างว่าการแจกสำเร็จ. Input จำกัด sample quest 1–20, completed quest 0–20 และ inventory slots 0–40.

`creator.dependencyGraph.questRewardInventoryPreview` และ Thai Workbench เป็น developer-only read-only preview. Workbench แสดง inventory dry-run accepted/blocked, reward dispatch ที่ขาด และ ability owner blocker โดยไม่เป็น player control. Preview ไม่เรียก `addItemToContainer` เพื่อเขียน state จริง, ไม่เรียก reward handler, ไม่ complete quest, ไม่ unlock ability/map, ไม่เขียน IndexedDB/Cache Storage/DB และคง runtime import/player visibility/cache เป็น false.

## กฎที่บังคับ

Generator version ต้องเป็น `x.y.z` และ registry จะเลือก version ล่าสุดด้วยการเปรียบเทียบตัวเลขของ semantic version ไม่ใช่การเรียงตัวอักษร. Generator ต้องถูก register ก่อนใช้; id ซ้ำกับ version เดิมถูกปฏิเสธ; unknown generator/version ถูกปฏิเสธ; output ที่ plugin validation ไม่ผ่านจะไม่กลายเป็น artifact ที่ใช้ export ได้

การ validate หลัง generate จะตรวจ schema, identity/provenance, seed, source, kind, asset references, content hash และ plugin-specific output rules. หาก artifact ถูกแก้ไขภายหลัง hash หรือ plugin validation จะไม่ผ่าน และ `save`/`export` จะโยน `GeneratorValidationError`

## ขอบเขตที่ยังไม่อ้างว่าเสร็จ

Foundation นี้มี Common Generator API และ dependency graph validator แต่ยังไม่มี orchestrator ที่ดึง artifact จริงจากทุก domain มาต่อ graph เดียวโดยอัตโนมัติ และยังไม่มี Structure/World/Quest/Dungeon/Loot/Item/Animation/Audio/Weather หรือ no-code UI generator รายด้านที่ emit dependency metadata ครบทุกตัว. ยังไม่มีการเขียนไฟล์ content ลง disk/database อัตโนมัติ และไม่มี player-facing generator route. สิ่งเหล่านี้จะเพิ่มเป็น plugin/tool checkpoint แยก โดยต้องใช้ contract นี้และผ่าน test, validation, provenance, performance review และ Git checkpoint ก่อน register เป็น content ที่ runtime ใช้ได้

Plant catalog generator เดิมยังคงเป็น runtime owner ของ plant/seed/harvest/soil relationships; checkpoint นี้เพิ่ม adapter สำหรับตรวจ dependency กับ `content.catalog` โดยไม่ rewrite owner และคง backward compatibility ของ farming slice. Exact references ที่ catalog ยังไม่มีจงใจทำให้ graph invalid เพื่อไม่หลอกให้ registry/runtime เห็น content ที่ยังไม่พร้อม

## Quest reward dispatch contract

`client/src/game/systems/questRewardDispatchSystem.ts` เป็น pure transition boundary สำหรับการตรวจว่า quest completion และ item reward สามารถเดินหน้าพร้อมกันแบบ atomic ได้หรือไม่ โดยรับ `StoryProgressState`, inventory, discovered item IDs, canonical quest reward data, runtime map ID, timestamp input และ deterministic sequence base แล้วคืนผลลัพธ์ใหม่หรือ failure ที่ยังคง state/input เดิมไว้ การทำงานนี้ไม่เรียก `saveSession`, ไม่เขียน localStorage/IndexedDB, ไม่ส่ง gameplay event และไม่ทำให้ planned map กลายเป็น playable map

เส้นทาง item reward ที่พิสูจน์ได้ใช้ `createMapRewardInstance` และ `addItemToContainer` กับ `PLAYER_INVENTORY_SLOTS` จำนวน 40 ช่อง โดยสร้าง provenance event ID รูปแบบ `quest-reward:<questId>:<rewardIndex>` และตรวจ duplicate provenance ก่อนเพิ่มของ หาก reward ใดเพิ่มไม่ได้ ระบบจะคืน failure แบบ atomic ไม่ยอมเก็บ reward ก่อนหน้าไว้บางส่วน และไม่เปลี่ยน story completion state

ปัจจุบัน generator ของ quest ยังใส่ `reputation` ใน reward และใส่ `abilityId` ในเควสสุดท้ายของแผนที่ ระบบจึง fail closed เพราะยังไม่มี canonical reputation owner หรือ ability runtime owner การมี item catalog/factory ไม่ได้แปลว่ามี caller ที่แจก reward จริง และ pure transition นี้ยังไม่ถูกต่อเข้า `ArcaneFrontier/rewardHandler` หรือ persistence caller จนกว่าจะมี integration checkpoint แยกพร้อม acceptance evidence

`server/generators/questRewardDispatchDependencyGraph.ts` เป็น read-only preview adapter ที่ใช้ quest progression จริงและตรวจ candidate quest ของ MAP_001 โดยสร้าง dependency graph สำหรับ story completion, item/inventory transition และ persistence/ability owners ที่ยังขาด Graph preview ถูกเปิดผ่าน `creator.dependencyGraph.questRewardDispatchPreview` ซึ่งอยู่หลัง creator guard สำหรับ GM/admin/master และคืน `previewOnly: true` พร้อม runtime policy `{ runtimeImportAllowed: false, playerVisible: false, cacheable: false }` เท่านั้น

การทดสอบ pure อยู่ที่ `server/questRewardDispatchSystem.test.ts` และ `server/questRewardDispatchDependencyGraph.test.ts`; authorization/preview contract อยู่ใน `server/creatorRouter.test.ts` โดยต้องยืนยัน item-only atomic success, capacity failure, missing definition, duplicate provenance, future-map rejection, missing reputation/ability owner, deterministic output, preview-only behavior และ `FORBIDDEN` สำหรับผู้ใช้ทั่วไปหรือ unauthenticated caller
