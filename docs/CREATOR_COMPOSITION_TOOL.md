# Thai Creator Composition Tool

`creator.composition.preview` เป็น developer-only no-code tool สำหรับประกอบ pixel/template metadata จากช่องที่คนใช้งานเข้าใจได้. ผู้สร้างเลือกประเภทสิ่งที่จะประกอบ, รหัส template, ขนาด canvas, สีพื้น/เส้นขอบ และสัดส่วนของส่วนหลัก แล้วใช้ pixel grid คลิกเติม/ลบเซลล์บน layer ที่เลือกด้วย palette. ระบบจะประกอบ layer `base`/`outline`, part `body`, palette ที่มี semantic และ sparse pixel cells ที่อ้างอิง `layerId` ให้เป็น composition manifest โดยไม่ให้ผู้ใช้เขียน JSON หรือกำหนด triangle mesh

| ส่วน | สิ่งที่ระบบตรวจ |
|---|---|
| Template | เลือกจาก shared `creatorTemplateCatalog.ts` ซึ่งเก็บ id/title/category/kind/dimensions เดียวกับ CreatorStudio; pure policy map `tile→block`, `skin→animation`, `weapon-icon→weapon`, icon อื่น→item และ Workbench แสดงเฉพาะ preset ที่ไม่เกิน 32×32 |
| Canvas | กว้าง/สูง 1–128 pixels และคำนวณ pixel budget |
| Layers | id ไม่ซ้ำ, role, z-index, visible และ opacity 0–1 |
| Parts | slot, ขนาด/พิกัดต้องอยู่ใน canvas และอ้างอิง layer ที่มีอยู่ |
| Palette | id ไม่ซ้ำ, hex สีถูกต้อง และ semantic ของสี |
| Pixel cells | x/y ต้องอยู่ใน canvas, `layerId` ต้องมีจริง, color id ต้องมีใน palette, ห้ามพิกัดซ้ำภายใน layerเดียวกัน และเรียงลำดับเพื่อ hash ที่ deterministic; พิกัดเดียวกันคนละ layer ซ้อนได้ |
| Safety | reject binary/geometry keys เช่น base64, bytes, mesh, vertices, indices, glb, obj |
| Registry | สร้าง metadata hash/provenance ด้วย `creator.composition@1.0.0` และ runtime policy ปิด |
| Texture handoff | `creator.composition.texturePreview` flatten sparse cells ตาม layer z-index/visibility/opacity แล้วแปลงเป็น RGBA ผ่าน existing `texture.pack` builder พร้อม composition SHA ใน provenance; `block/structure→tile`, `item/weapon→icon`, `animation→skin` และ animation จะสร้าง `skinLayout` จาก composition parts; เป็น transient preview เท่านั้น |
| Texture export | `creator.composition.exportPreview` ตรวจ PNG bytes/asset SHA/manifest hash แล้วคืน export bundle พร้อม `downloadFileName` และ `pngBase64`; คืน `manifest.json` sidecar แบบ UTF-8 deterministic พร้อม SHA-256 และ deterministic ZIP ที่รวม manifest กับ relative PNG paths; `creator.composition.byteCompatibility` ตรวจ bytes/hash/file list ซ้ำพร้อม reason codes; `creator.composition.register` เป็น action แยกสำหรับส่ง output ที่ผ่าน preflight ไป durable texture registry; การดาวน์โหลด PNG/manifest/ZIP ต้องกดปุ่มเองและยังต้อง review แยก |
| Texture review | `creator.texture.review` ใช้ transition policy กลาง: `draft→approved`, `draft→rejected` ต้องมีหมายเหตุ และ `rejected→draft` ต้องมีหมายเหตุ; `creator.texture.list` กรองสถานะได้ และ `creator.texture.audit` อ่าน immutable review events; ทั้งหมดเป็น admin-only และ approved ไม่ได้แปลว่า import/publish/cache เข้า player |

ผลลัพธ์ composition มี `previewOnly: true`, `meshRequired: false`, `runtimeImportAllowed: false`, `playerVisible: false` และ `cacheable: false`. `registryMetadata` ต่อเข้ากับ generic creator artifact registry ได้ภายหลัง. `creator.composition.texturePreview` ใช้ `creatorCompositionTextureAdapter.ts` ส่งข้อมูลไป existing `texture.pack` builder เพื่อสร้าง PNG preview ชั่วคราวสำหรับผู้ดูแล พร้อม SHA-256/provenance; ไม่เรียก texture registry, ไม่ upload storage, ไม่เปลี่ยน review state และไม่ publish เข้าเกมโดยอัตโนมัติ. `creator.composition.exportPreview` ใช้ `creatorCompositionTextureExport.ts` ตรวจ output เดิมอีกชั้นและสร้าง `manifest.json` sidecar จาก texture-pack manifest ด้วย stable JSON + newline จากนั้น hash bytes ด้วย SHA-256; `creatorCompositionTextureBundle.ts` รวม sidecar และทุก PNG ตาม relative path เป็น ZIP ที่เรียงไฟล์และใช้ fixed metadata เพื่อให้ bytes/hash deterministic; export identity ผูกกับ composition SHA + pack SHA + manifest SHA + bundle SHA + asset hashes; `creator.composition.byteCompatibility` ใช้ `creatorCompositionTextureCompatibility.ts` parse manifest/PNG/ZIP, ตรวจ SHA-256, PNG signature, ZIP central/local records, CRC, decompression, file list และ byte parity พร้อม reason codes ก่อนรายงาน `compatible` หรือ `blocked`; export route คืน bytes เป็น metadata ของ bundleสำหรับปุ่มดาวน์โหลด PNG/manifest/ZIP ส่วน compatibility route คืนผลตรวจเท่านั้น; `creator.composition.register` เรียก `buildVerifiedCreatorCompositionTexture` ซึ่งสร้าง output ใหม่และตรวจ byte compatibility ก่อนเรียก `registerTexturePackArtifact` owner เดิมเพื่อเก็บ PNG/manifest แบบ durable เมื่อมี DATABASE_URL และ object storage ที่ตั้งค่าแล้ว; การ register ใหม่มี review status `draft`. `creator.texture.review` อัปเดต status แบบ atomic ผ่าน existing transition policy และเขียน `creatorArtifactReviewEvents` แยกอย่าง immutable ใน migration เพิ่มเติม `0007_texture_artifact_review.sql`; `creator.texture.list` และ `creator.texture.audit` อ่านสถานะ/ประวัติจาก owner เดิม. ZIP ยังเป็น download-only bundle และไม่มี auto-publish. ทั้งหมดเป็น action ที่ผู้ดูแลสั่งเอง โดย `runtimeImportAllowed`, `playerVisible` และ `cacheable` ยังคงปิด

`client/src/lib/creatorTemplateCatalog.ts` เป็น source-of-truth ของ template และ skin-part layout ที่ CreatorStudio กับ Workbench ใช้ร่วมกัน; animation composition handoff ใช้ `composition-parts-v1` เป็น skin layout และส่งผ่าน existing skin validation ก่อนสร้าง `skins/*.png`; Workbench ไม่เปิด atlas หรือ preset ที่เกิน 32×32 ซึ่ง grid รอบนี้แสดงไม่ได้. เมื่อเปลี่ยน template ระบบใช้ dimensions/subject จาก preset และล้าง pixel draft เดิมเพื่อไม่ให้พิกัดของงานก่อนหน้าไหลข้าม template. Workbench ใช้ route `/creator-workbench` หลัง `CreatorAccessGate` และการ preview ใช้ `adminProcedure`. `CreatorPixelGridEditor` แสดงผลและแก้ไขได้ไม่เกิน 32 × 32 ใน UI รอบนี้ พร้อมตัวเลือก layer; pure validator/schema ยังรับ manifest สูงสุด 128 × 128 และสูงสุด 16,384 cells. Player landing/game ไม่มี composition domain, form หรือผลลัพธ์ของ creator tool. Composition สำหรับสกิน/แอนิเมชันใน checkpoint นี้หมายถึง manifest ของส่วนประกอบ สัดส่วน และพิกัด pixel ไม่ใช่ skeleton, clip หรือ model asset ที่เสร็จสมบูรณ์

> **ข้อจำกัด:** pixel grid เป็น editor แบบ bounded click-to-paint ที่เก็บ sparse cells; texture handoff/export/byte compatibility สร้าง ตรวจ และคืน PNG, `manifest.json` sidecar และ ZIP package สำหรับ preview/download ที่ผู้ดูแลสั่งเท่านั้น; มี explicit register และ review/list/audit routes ที่ reuse durable texture registry พร้อม migration `0007_texture_artifact_review.sql` แต่ยังไม่มี DATABASE_URL/object-storage registration หรือ review E2E, migration/db push ที่อนุมัติแล้ว, texture atlas export, multi-asset domain package policy, undo/redo, skeleton/rig, actual model assembly, durable runtime asset compatibility/publish workflow หรือ runtime import. สิ่งเหล่านี้ต้องแยก checkpoint พร้อม asset provenance และ visual evidence ต่อไป
